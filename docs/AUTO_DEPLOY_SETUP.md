# Настройка автоматического деплоя на VPS

Этот документ описывает, как настроить автоматический деплой через GitHub Actions.

## Как это работает

При каждом `git push` в ветку `main`:
1. GitHub Actions запускается автоматически
2. Подключается к VPS по SSH
3. Выполняет `git pull` на VPS
4. Пересобирает Docker образы
5. Перезапускает контейнеры
6. Выполняет миграции и собирает статику

---

## Настройка (выполнить один раз)

### Шаг 1: Создать SSH ключ для деплоя на VPS

**На вашей локальной машине выполните:**

```bash
# Создать новый SSH ключ для деплоя
ssh-keygen -t ed25519 -C "github-actions-deploy" -f ~/.ssh/github_deploy_key

# НЕ устанавливайте пароль - просто нажмите Enter
```

Это создаст два файла:
- `~/.ssh/github_deploy_key` - приватный ключ (секретный)
- `~/.ssh/github_deploy_key.pub` - публичный ключ (можно показывать)

---

### Шаг 2: Добавить публичный ключ на VPS

**Скопируйте содержимое публичного ключа:**

```bash
cat ~/.ssh/github_deploy_key.pub
```

**Подключитесь к VPS и добавьте ключ:**

```bash
# На VPS
ssh root@5.188.138.16

# Добавить публичный ключ в authorized_keys
echo "ВСТАВЬТЕ_СЮДА_СОДЕРЖИМОЕ_github_deploy_key.pub" >> ~/.ssh/authorized_keys

# Установить правильные права
chmod 600 ~/.ssh/authorized_keys
chmod 700 ~/.ssh

# Выйти
exit
```

---

### Шаг 3: Проверить подключение

**На локальной машине проверьте, что можете подключиться с новым ключом:**

```bash
ssh -i ~/.ssh/github_deploy_key root@5.188.138.16

# Если подключились успешно - всё работает!
exit
```

---

### Шаг 4: Добавить секреты в GitHub

**Скопируйте приватный ключ:**

```bash
cat ~/.ssh/github_deploy_key
```

**Скопируйте весь вывод (включая строки `-----BEGIN` и `-----END`)**

**Перейдите в настройки GitHub репозитория:**

1. Откройте ваш репозиторий на GitHub
2. Перейдите: **Settings** → **Secrets and variables** → **Actions**
3. Нажмите **New repository secret**

**Добавьте следующие секреты:**

| Name | Value | Описание |
|------|-------|----------|
| `VPS_HOST` | `5.188.138.16` | IP адрес VPS |
| `VPS_USERNAME` | `root` | Пользователь SSH (обычно root) |
| `VPS_SSH_KEY` | Содержимое `~/.ssh/github_deploy_key` | Приватный SSH ключ (весь текст) |
| `VPS_PORT` | `22` | SSH порт (обычно 22) |

**Важно:** При добавлении `VPS_SSH_KEY` скопируйте весь ключ целиком, включая:
```
-----BEGIN OPENSSH PRIVATE KEY-----
...содержимое ключа...
-----END OPENSSH PRIVATE KEY-----
```

---

### Шаг 5: Скопировать скрипт деплоя на VPS

**На вашей локальной машине:**

```bash
# Скопировать deploy.sh на VPS
scp deploy.sh root@5.188.138.16:/opt/metatecks/

# Или, если используете новый ключ:
scp -i ~/.ssh/github_deploy_key deploy.sh root@5.188.138.16:/opt/metatecks/
```

**На VPS:**

```bash
ssh root@5.188.138.16
cd /opt/metatecks
chmod +x deploy.sh
exit
```

## Использование

### Автоматический деплой

Просто делайте `git push` в ветку `main`:

```bash
git add .
git commit -m "Update something"
git push origin main
```

GitHub Actions автоматически:
- Подключится к VPS
- Обновит код
- Пересоберёт Docker
- Перезапустит контейнеры

**Проверить статус деплоя:**
- Перейдите на GitHub в ваш репозиторий
- Откройте вкладку **Actions**
- Увидите список запусков деплоя

---

### Ручной деплой

Если нужно обновить VPS вручную (без git push):

```bash
# На VPS
ssh root@5.188.138.16
cd /opt/metatecks
./deploy.sh
```

## Мониторинг деплоя

### Просмотр логов на VPS

```bash
# Подключиться к VPS
ssh root@5.188.138.16

# Перейти в директорию проекта
cd /opt/metatecks

# Посмотреть логи контейнеров
docker-compose logs -f web
```

1. Откройте ваш репозиторий на GitHub
2. Перейдите на вкладку **Actions**
3. Выберите нужный запуск workflow
4. Посмотрите детальные логи каждого шага

## Безопасность

✅ **Рекомендации:**
- SSH ключ для деплоя создан отдельно (не ваш основной ключ)
- Приватный ключ хранится только в GitHub Secrets (зашифрован)
- Ключ имеет доступ только к VPS, не к другим сервисам
- После удаления ключа из VPS деплой перестанет работать

❌ **НЕ делайте:**
- Не коммитьте приватный ключ в Git
- Не публикуйте приватный ключ в открытом доступе
- Не используйте один ключ для всех проектов

## Устранение проблем

### Ошибка: Permission denied (publickey)

**Причина:** GitHub Actions не может подключиться к VPS

**Решение:**
1. Проверьте, что публичный ключ добавлен в `~/.ssh/authorized_keys` на VPS
2. Проверьте права на файлы:
   ```bash
   chmod 600 ~/.ssh/authorized_keys
   chmod 700 ~/.ssh
   ```
3. Проверьте, что в GitHub Secrets добавлен правильный **приватный** ключ

---

### Ошибка: Docker build failed

**Причина:** Ошибка при сборке Docker образа

**Решение:**
1. Проверьте логи в GitHub Actions
2. Подключитесь к VPS и выполните сборку вручную:
   ```bash
   cd /opt/metatecks
   docker-compose build
   ```
3. Исправьте ошибки в коде или Dockerfile

---

### Деплой работает, но сайт не открывается

**Причина:** Контейнеры запустились, но приложение не работает

**Решение:**
```bash
# На VPS
cd /opt/metatecks

# Проверить статус
docker-compose ps

# Посмотреть логи
docker-compose logs web

# Проверить доступность
curl http://127.0.0.1:8080
curl http://127.0.0.1:8001
```

## Дополнительные возможности

### Деплой только при изменении определенных файлов

Можно настроить деплой только при изменении Python/Docker файлов:

```yaml
on:
  push:
    branches:
      - main
    paths:
      - '**.py'
      - 'requirements.txt'
      - 'Dockerfile'
      - 'docker-compose.yml'
```

### Уведомления в Telegram

Можно добавить отправку уведомлений в Telegram при успешном/неудачном деплое.

### Деплой в staging перед production

Можно настроить двухэтапный деплой:
1. Push в `develop` → деплой на staging сервер
2. Push в `main` → деплой на production сервер
