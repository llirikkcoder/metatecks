# Как использовать Skills в Claude Code

## Что такое Skills?

Skills - это специализированные модули знаний для Claude Code, которые дают экспертизу в определенной области. Это как "профессиональные навыки" ассистента.

## Структура Skills

Skills хранятся в директории `.claude/skills/`:

```
.claude/
  skills/
    HOW_TO_USE_SKILLS.md    ← Эта инструкция
```

## Как работают Skills

### Автоматическое использование

Claude Code автоматически определяет, когда нужно использовать skill, основываясь на контексте вашего запроса.

### Явный вызов Skill

Вы можете явно попросить использовать конкретный skill:

```
Используй skill supabase-db и создай таблицу для хранения логов
```

## Доступные Skills

### 1. supabase-db

**Для чего:** Работа с базой данных Supabase PostgreSQL

**Возможности:**
- ✅ Создание миграций с правильным синтаксисом
- ✅ RLS (Row Level Security) политики
- ✅ RPC функции
- ✅ Оптимизация запросов и индексы
- ✅ Backup процедуры
- ✅ Подключение через CLI, Python, psql

**Когда использовать:**
- Создание/изменение таблиц
- Написание SQL запросов
- Настройка RLS
- Создание RPC функций
- Оптимизация производительности
- Работа с миграциями

**Пример использования:**
```
Вы: Добавь поле telegram_username в таблицу users

Claude (автоматически использует supabase-db skill):
- Напомнит создать backup
- Создаст миграцию с правильным синтаксисом
- Добавит индекс если нужно
- Создаст rollback скрипт
```

## Примеры практического использования

### Пример 1: Создание миграции

**Ваш запрос:**
```
Создай таблицу notifications с полями:
- id (UUID)
- user_id (UUID, foreign key)
- message (TEXT)
- read_at (TIMESTAMP)
- created_at (TIMESTAMP)
```

**Что сделает Claude (с supabase-db skill):**
1. Напомнит о создании backup перед миграцией
2. Создаст migration файл с:
   - Правильными типами данных (TIMESTAMP WITH TIME ZONE, не просто TIMESTAMP)
   - UUID PRIMARY KEY DEFAULT gen_random_uuid()
   - Foreign key constraint
   - Индексами на user_id
   - RLS политиками
   - Триггером для updated_at
3. Создаст rollback скрипт

### Пример 2: RPC функция

**Ваш запрос:**
```
Создай RPC функцию get_unread_notifications для получения непрочитанных уведомлений пользователя
```

**Что сделает Claude (с supabase-db skill):**
1. Создаст функцию на pl/pgsql с правильным синтаксисом
2. Добавит SECURITY DEFINER если нужно
3. Покажет как вызвать из Python через supabase client
4. Добавит пример использования

### Пример 3: Подключение к базе

**Ваш запрос:**
```
Как подключиться к базе данных через Python?
```

**Что сделает Claude (с supabase-db skill):**
1. Покажет правильный connection string (Transaction Pooler)
2. Даст примеры через DatabaseManager проекта
3. Покажет прямое подключение через psycopg2
4. Покажет как использовать Supabase client
5. Все примеры будут работать с `.env.local` файлом

### Пример 4: Оптимизация запроса

**Ваш запрос:**
```
Запрос SELECT * FROM deals WHERE user_id = X AND status = 'active' медленный
```

**Что сделает Claude (с supabase-db skill):**
1. Проверит наличие индексов
2. Предложит создать composite index на (user_id, status)
3. Покажет EXPLAIN ANALYZE для анализа
4. Даст рекомендации по оптимизации

## Что НЕ делают Skills

**Skills НЕ:**
- ❌ Не выполняют код автоматически (вы контролируете выполнение)
- ❌ Не изменяют базу данных без вашего разрешения
- ❌ Не пропускают проверки безопасности

**Skills ВСЕГДА:**
- ✅ Напоминают о backup перед миграциями
- ✅ Следуют best practices
- ✅ Создают rollback скрипты
- ✅ Используют правильный синтаксис

## Правила работы с supabase-db Skill

### Обязательные правила (ВСЕГДА):

1. **Backup перед миграцией:**
   - Skill ВСЕГДА напомнит создать backup
   - Даст инструкцию: Supabase Dashboard → Database → Backups
   - Попросит назвать backup: `pre-[feature]-[date]`

2. **PostgreSQL синтаксис:**
   - `true/false` вместо `1/0` для boolean
   - `TIMESTAMP WITH TIME ZONE` вместо просто `TIMESTAMP`
   - `TEXT` вместо `VARCHAR` (если нет ограничения длины)
   - `JSONB` вместо `JSON` для производительности

3. **RLS (Row Level Security):**
   - Всегда предложит RLS для таблиц с пользовательскими данными
   - Покажет примеры политик
   - Объяснит что делает каждая политика

4. **Rollback стратегия:**
   - Каждая миграция будет иметь rollback скрипт
   - Rollback будет безопасным (IF EXISTS, IF NOT EXISTS)

## Советы по эффективному использованию

### 1. Будьте конкретны

**❌ Плохо:**
```
Сделай что-то с базой данных
```

**✅ Хорошо:**
```
Добавь поле telegram_username VARCHAR(255) в таблицу users
с уникальным индексом
```

### 2. Контекст помогает

**❌ Плохо:**
```
Создай таблицу
```

**✅ Хорошо:**
```
Создай таблицу notifications для хранения уведомлений пользователей.
Нужны поля: user_id (ссылка на users), message, read_at
```

### 3. Уточняйте требования

**✅ Хорошо:**
```
Создай RPC функцию get_active_deals, которая:
- Принимает user_id
- Возвращает только активные сделки
- Доступна только владельцу
```

### 4. Спрашивайте о лучших практиках

**✅ Полезные вопросы:**
- "Какой индекс лучше для этого запроса?"
- "Нужен ли RLS для этой таблицы?"
- "Как оптимизировать этот запрос?"
- "Какой connection mode использовать?"

## Часто задаваемые вопросы

### Q: Как узнать, используется ли skill?

A: Claude явно укажет, если использует специализированный skill, или вы можете попросить:
```
Используй skill supabase-db для этой задачи
```

### Q: Можно ли отключить skill?

A: Да, просто укажите:
```
Не используй skill, сделай обычным способом
```

### Q: Skills работают только с базой данных?

A: Нет! Можно создать skills для любой области:
- Telegram бот
- AI агенты
- React компоненты
- DI (dishka)
- CRM интеграции
- И любой другой домен проекта

### Q: Нужно ли что-то настраивать?

A: Нет, skills работают автоматически. Просто задавайте вопросы или давайте задачи.
